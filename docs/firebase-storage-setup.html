เปิด Cloud Storage สำหรับอัปโหลด PDF/รูป (production)

Legacy: ตั้งแต่ Phase 1 ไฟล์ใหม่อัปโหลดไป Vercel Blob แล้ว — ดู vercel-blob-setup.html. เอกสารนี้เก็บไว้สำหรับไฟล์เก่าบน Firebase Storage เท่านั้น

โปรเจกต์: cntdev-e49f5
Console: https://console.firebase.google.com/project/cntdev-e49f5

เมนู Build → Storage ในเอกสารเก่าไม่มีแล้ว — ใช้ Databases & Storage → Storage แทน

ทำไมต้องเปิด Storage

  • Firestore เก็บข้อความข่าว (หัวข้อ, วันที่, ลิงก์) ได้อยู่แล้ว
  • Cloud Storage เก็บไฟล์ PDF/รูป — ถ้ายังไม่เปิด บน Vercel อัปโหลดไฟล์จาก admin จะไม่สำเร็จ

ทางเลือกชั่วคราว: ใน admin ข่าว → ไม่อัปโหลด PDF → วาง ลิงก์ Google Drive ในช่อง「ลิงก์เอกสาร」แทน (ทำงานได้ทันทีโดยไม่ต้องเปิด Storage)

ขั้นตอนใน Firebase Console (UI ปัจจุบัน)

  1. เปิด Firebase Console → เลือกโปรเจกต์ cntdev-e49f5
  2. แถบซ้าย → Databases & Storage (อาจต้องกดลูกศรเพื่อขยาย)
  3. คลิก Storage
  4. ถ้าเห็นปุ่ม Get started → กดแล้วทำตาม wizard
  5. เลือก location (แนะนำ asia-southeast1 หรือใกล้ผู้ใช้ในไทย)
  6. เลือก security rules ตามที่ wizard แนะนำ (มักเริ่มจาก test mode แล้วค่อยเข้มงวดทีหลัง)

ถ้าไม่เห็น Storage / ขึ้นให้อัปเกรดแผน

Cloud Storage for Firebase ต้องใช้แผน Blaze (pay-as-you-go):

  1. แถบซ้ายล่าง → Upgrade (หรือ Project settings → Usage and billing)
  2. อัปเกรดเป็น Blaze
  3. ตั้ง billing alert ใน Google Cloud (แนะนำ) — ใช้น้อยมักอยู่ใน free tier ของ Storage

หลังเปิด Storage แล้ว → Redeploy บน Vercel แล้วลองอัปโหลด PDF อีกครั้ง

ทางเลือก: Google Cloud Console

ถ้าใน Firebase ยังหาไม่เจอ:

  1. https://console.cloud.google.com/storage/browser?project=cntdev-e49f5
  2. ถ้ายังไม่มี bucket → Create bucket
  3. ชื่อ bucket มักเป็น cntdev-e49f5.firebasestorage.app หรือ cntdev-e49f5.appspot.com (ดูใน Firebase → Storage → Files หลังเปิดใช้)

ตรวจว่าเปิดสำเร็จ

ใน Firebase → Databases & Storage → Storage → Files ควรเห็นหน้ารายการ bucket (อาจว่าง ยังไม่มีไฟล์)

จากนั้นอัปโหลด PDF จาก admin บน production ควรสำเร็จ และ link ในข่าวจะชี้ไป URL บน Storage

CORS สำหรับอัปโหลดตรงจาก browser (จำเป็นบน production)

Admin อัปโหลด PDF และรูปภาพ ตรงไป bucket (ไม่ผ่าน body ของ Vercel Function) — browser ต้องได้รับอนุญาตจาก bucket

  1. เปิด Google Cloud Console → Cloud Storage → bucket ของโปรเจกต์
  2. แท็บ Configuration → CORS → Edit
  3. ใส่ config ตัวอย่าง (ปรับ origin ถ้ามีโดเมน custom):
[
      {
        "origin": ["https://cntdev.vercel.app", "http://localhost:6395", "http://127.0.0.1:6395"],
        "method": ["PUT", "GET", "HEAD"],
        "responseHeader": ["Content-Type", "x-goog-resumable"],
        "maxAgeSeconds": 3600
      }
    ]
  1. บันทึก แล้วลองอัปโหลด PDF จาก admin อีกครั้ง

ถ้า CORS ไม่ตั้ง จะเห็นข้อความ "อัปโหลดไฟล์ไป Cloud Storage ไม่สำเร็จ" ใน admin

ทางเลือก: ใช้ gsutil cors set cors.json gs://YOUR_BUCKET_NAME จากเครื่องที่ติดตั้ง Google Cloud SDK

Local dev (npm run dev)

โปรเจกต์นี้รันที่ http://localhost:6395 (ตั้งใน vite.config.js) — ไม่ใช่ พอร์ต 5173 (พอร์ตนั้นมักเป็นโปรเจกต์อื่น เช่น kp7-react)

บน localhost ระบบจะ ไม่ ส่ง PDF/รูปตรงจาก browser ไป bucket (เลี่ยง CORS) — อัปโหลดผ่าน API แล้ว server ใช้ Admin SDK แทน (หรือเขียนลง static/ ถ้าไม่มี Storage)

ถ้าต้องการทดสอบ flow อัปโหลดตรงเหมือน production บนเครื่องตัวเอง:

  1. ตั้ง CORS ให้รวม http://localhost:6395 (ดูด้านบน)
  2. ใน .env.local ใส่ PDF_DIRECT_UPLOAD_LOCAL=1
