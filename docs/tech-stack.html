ผู้ใช้ → Vercel (SvelteKit)
             ├─ หน้าสาธารณะ (อ่าน API / static)

Tech Stack

รายละเอียดแต่ละประเภท

ข่าวประชาสัมพันธ์ (news)
API อ่าน GET /api/news
API เขียน POST / PUT / DELETE /api/news
API ลำดับ POST /api/news/reorder — admin ลาก ☰ แล้วบันทึกทันที
เอกสาร (PDF) เก็บ URL ใน field link — วางลิงก์ Google Drive ใน admin (ไม่อัปโหลดบนเว็บ)
PDF production ลิงก์ Google Drive (แชร์「ทุกคนที่มีลิงก์」)
PDF dev ลิงก์ Drive หรือ URL ใน static/assets/documents/news/ (รายการเก่า)
โค้ด PDF ลิงก์ Google Drive ใน admin — ดู google-drive-workflow.html
ขีดจำกัดไฟล์ PDF: ลิงก์ Drive เท่านั้น; รูป 5 MB — src/lib/uploadLimits.js
ข้อความ error admin src/lib/adminFetch.js — แปล HTTP 401/403/413 เป็นภาษาไทย
หมายเหตุ PDF: google-drive-workflow.html; รูป: vercel-blob-setup.html
รูปปก image = logo สำรอง (assets/images/logos/moe.png)
หมวดหมู่ category = ข่าวประชาสัมพันธ์ เสมอ (API ตั้งให้ — ไม่มีใน admin)

ภาพกิจกรรม (activities)
API อ่าน GET /api/activities
API เขียน POST / PUT / DELETE /api/activities
API ลำดับ POST /api/activities/reorder — admin ลาก ☰ แล้วบันทึกทันที
รูป production Vercel Blob: activities/{filename}
รูป dev static/assets/images/activity/
โค้ดรูป src/lib/server/contentStore.js → saveImageFile('activities')

คู่มือ / คลังความรู้ / แผน / แบบฟอร์ม (manuals / knowledge / plans / forms)

ทำงานแบบเดียวกับข่าว — แต่ละรายการเป็น document แยก ใน collection ของตัวเอง เพิ่ม/แก้/ลบทีละรายการผ่าน modal ในหน้า admin
API อ่าน GET /api/site-data/{key} คืน { items, source } — เรียง sortOrder จากมาก→น้อย (ค่ามาก = แสดงก่อน; รายการใหม่ใช้ Date.now())
API เขียน POST / PUT / DELETE /api/site-data/{key} (ต่อรายการ)
API ลำดับ POST /api/site-data/{key}/reorder body { orderedIds } — admin ลาก ☰ แล้วบันทึกทันที (รวม personnel)
ฟิลด์ id, title, link, sortOrder
เอกสาร (PDF) เก็บ URL ใน field link — วางลิงก์ Google Drive ใน admin (ไม่อัปโหลดบนเว็บ)
PDF dev ลิงก์ Drive หรือ URL ใน static/assets/documents/{key}/ (รายการเก่า)
โค้ด src/lib/sortSiteOrder.js, src/lib/documentLink.js, src/routes/api/site-data/[key]/+server.js, src/routes/api/site-data/[key]/reorder/+server.js

อำนาจหน้าที่ (authority)

ยังเป็นโมเดล bulk — site_data document เดียว (array ของ string), แก้แบบ "บันทึกทั้งหมด" ใน admin

บุคลากร (personnel)

ทำงานแบบเดียวกับภาพกิจกรรม — แต่ละคนเป็น document แยกใน collection personnel
API อ่าน GET /api/site-data/personnel
API เขียน POST / PUT / DELETE /api/site-data/personnel (ต่อรายการ)
API ลำดับ POST /api/site-data/personnel/reorder — ลาก ☰ แล้วบันทึกทันที (sortOrder มาก = บน)
ฟิลด์ id, name, position, phone, image, sortOrder
อัปโหลดรูป ส่ง imageFile ใน FormData → saveImageFile('personnel')
รูป production Vercel Blob: personnel/{filename}
รูป dev static/assets/images/personnel/

migration ครั้งเดียวจาก site_data/{key} เดิม → collection ต่อรายการ: node scripts/migrate-lists-to-collections.mjs (ใช้ --force เพื่อ resync ทับข้อมูลเก่าใน collection ให้ตรงกับ site_data)

คลังเกียรติบัตร (certificates)
API อ่าน GET /api/certificates/config
API เขียน POST /api/certificates/config
ข้อมูลภายนอก Google Sheets CSV (sheetUrl ใน config)
โค้ด src/lib/server/certificatesConfig.js

Environment Variables

อย่าใส่ค่าจริงในเอกสาร — ตั้งบน Vercel (Production + Preview) และ .env.local เท่านั้น

ตัวแปร ประเภท ที่เก็บ จำเป็น คำอธิบาย
ADMIN_PASSWORD secret Vercel, .env.local production รหัสผ่าน admin (username คงที่: admin)
AUTH_SESSION_SECRET secret Vercel, .env.local production คีย์ลงนาม session cookie (สตริงสุ่มยาว 32+ ตัว)
PUBLIC_TURNSTILE_SITE_KEY public Vercel, .env.local optional Cloudflare Turnstile Site Key — ไม่ตั้ง = ข้าม widget
TURNSTILE_SECRET_KEY secret Vercel, .env.local optional Cloudflare Turnstile Secret — คู่กับ Site Key
FIREBASE_SERVICE_ACCOUNT_JSON secret Vercel, .env.local production JSON service account บรรทัดเดียว — เปิด Firestore/Storage บน production

ดูรายการใน .env.example
